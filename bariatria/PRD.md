# PRD: Бариатрия — приложение наблюдения за пациентами

## 1. Проблема

Хирург-бариатр ведёт ~20 пациентов после операции (мини-гастрошунтирование,
sleeve-резекция). Наблюдение — 12 месяцев, раз в месяц: вес, самочувствие,
витамины D и B12, гемоглобин. Сейчас сбор идёт вручную через WhatsApp и
Google Form — данные разрознены, нет истории по пациенту, нет напоминаний
о просрочке.

## 2. Цель

Дать врачу единый инструмент: пациент раз в месяц заполняет короткую форму
со своего телефона по постоянной ссылке; врач в любой момент открывает
панель и видит динамику веса и статус по каждому пациенту без ручного
сведения таблиц.

## 3. Пользователи

| Роль | Кто | Что делает |
|---|---|---|
| Пациент | человек после операции | один раз — первичная анкета; далее раз в месяц — контроль веса |
| Врач | Руслан Ерсайнович | открывает защищённую панель, смотрит список пациентов и график по каждому |

## 4. Объём (Scope)

### Входит в v1
- Форма первичной анкеты (один раз на пациента)
- Форма ежемесячного контроля (повторяется 12 раз)
- Панель врача: список пациентов, статус контроля, график веса, история
- Хранение данных в Google Таблице (два листа: «Пациенты», «Контроль»)
- Доступ пациента — по прямой ссылке, без регистрации
- Доступ врача — по ссылке с секретным ключом

### Не входит в v1
- Автоматические напоминания пациентам (WhatsApp/email/календарь)
- Push-уведомления врачу о просрочке
- Мультивраченый доступ (несколько хирургов в одной базе)
- Редактирование/удаление уже отправленных записей пациентом
- Экспорт в PDF/отчёты

## 5. Функциональные требования

### 5.1 Первичная анкета (`/exec`)
Обязательные поля: ФИО, телефон, вес до операции, согласие на обработку данных.
Необязательные: дата рождения, пол, email, дата и вид операции, рост,
сопутствующие заболевания.
Валидация: вес 30–350 кг.
Результат: одна строка в листе «Пациенты».

### 5.2 Ежемесячный контроль (`/exec?page=checkin`)
Обязательные поля: ФИО, телефон, вес.
Необязательные: дата взвешивания, талия, самочувствие (1–5), жалобы
(мультивыбор), вода, белок, активность, витамины, гемоглобин, ферритин,
витамин D, витамин B12, комментарий.
Валидация: вес 30–350 кг.
Результат: одна строка в листе «Контроль», привязана к пациенту по номеру
телефона (нормализуется — только цифры).

### 5.3 Панель врача (`/exec?page=dashboard&key=...`)
- Доступ только по совпадению секретного ключа в ссылке
- Сводка: всего пациентов, всего записей контроля, просрочили контроль
  (>35 дней с последней записи), ни разу не отмечались
- Таблица пациентов: ФИО, телефон, тип операции, вес начальный → текущий,
  сколько сброшено, статус контроля (цвет: ок / скоро / просрочен)
- Поиск по ФИО и телефону
- Карточка пациента: сводные показатели, график веса по всем записям
  (SVG), последняя запись контроля целиком

## 6. Модель данных

**Лист «Пациенты»**: отметка времени, ФИО, телефон, дата рождения, пол,
email, дата операции, вид операции, рост, вес до операции, заболевания,
согласие.

**Лист «Контроль»**: отметка времени, ФИО, телефон, дата взвешивания, вес,
талия, самочувствие, жалобы, вода, белок, активность, витамины, гемоглобин,
ферритин, витамин D, витамин B12, комментарий.

Связь пациент ↔ контроль — по нормализованному номеру телефона (единственный
идентификатор в v1; риск: пациент вводит номер по-разному → запись не
привяжется к истории).

## 7. Технические решения

- **Платформа**: Google Apps Script (Web App) + Google Таблица как БД
- **Почему не Google Forms**: нет единого дизайна, нельзя сделать дашборд
  с графиком на тех же данных без доп. инструментов
- **Почему не Claude Artifact с живой базой**: база данных артефакта
  доступна только участникам той же организации Claude — пациенты,
  открывающие ссылку со стороны, не смогли бы писать данные
- **Защита панели врача**: секретный ключ в query-параметре (без него —
  «Доступ запрещён»); ключ задаётся вручную в CONFIG
- **Хостинг**: бесплатный, в личном Google-аккаунте врача, без внешнего
  сервера

## 8. Метрики успеха

- Пациент заполняет ежемесячный контроль без звонка/напоминания от врача
- Врач видит статус всех пациентов за один просмотр панели, без сведения
  вручную
- Ни одной потерянной записи (вся история пациента — в одной таблице)

## 9. Риски и ограничения

| Риск | Последствие | Смягчение в v1 |
|---|---|---|
| Пациент вводит телефон по-разному | запись контроля не привяжется к пациенту | нормализация телефона (только цифры) |
| Нет напоминаний | пациент забывает про месячный контроль | ручная отправка ссылки врачом (в бэклоге — автонапоминания) |
| Ключ панели попадёт не в те руки | доступ к медицинским данным | ключ передаётся только врачу, не публикуется |
| Данные не защищены шифрованием на уровне БД | утечка при компрометации Google-аккаунта врача | стандартная защита Google-аккаунта (2FA) — ответственность врача |

## 10. Открытые вопросы

- Нужно ли пациенту видеть свою историю (например, свой график)?
- Нужны ли автоматические напоминания через WhatsApp/календарь на дату
  операции +1, +2, ... +12 месяцев?
- Что делать по истечении 12 месяцев — архивировать пациента или продолжать
  сбор данных?
